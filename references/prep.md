# 1on1準備

対象者との面談を担当する運用者向けメモを作る。入力は保存済みローカル資料に限定し、直前の外部接続の成否へ依存しない。

## 入力

| 資料 | 読む範囲 | 不足時の扱い |
|---|---|---|
| goals.md | 現在の目標と確認日、本人確認済みの言葉 | 未記入・確認日不明と明示 |
| activity | 面談前の直近14日。月境界は前月ファイルも読む | 収集できていない期間を明示 |
| meetings | 最新の取込済みTranscriptと参加者・話者 | 未取込・話者不明・判読不可と明示 |
| prep | 前回メモの根拠と確認項目 | 前回資料なしと明示 |

Slack・Notionへ新たな活動読み取りを行わない。資料が不足する場合は、collect・meeting-importを別処理として案内する。対象者の特定にCalendarを使う場合は、[定期実行の1on1条件](scheduling.md)を確認する。

## 6章の構成

1. **直近14日の事実**：日付・出典付きで記録する。欠測期間を「活動なし」としない。
2. **目標との照合**：目標、確認済み事実、達成／進行中／判断材料なしを表にする。目標の原文・確認日は維持する。
3. **本人がやりたいこと**：本人の言葉・Transcriptの話者を根拠として記す。AI要約や運用者の期待を本人希望にしない。
4. **問いの案**：最大3つ。問いごとに根拠となる事実を添える。答えを先に決めない。
5. **運用者の解釈**：推測・懸念・仮説はこの章に限定し、事実とは分ける。
6. **前回のネクストアクション**：本人の明示した約束・合意と出典を示す。抽出できない場合は「前回アクション未確認」と書く。

1〜4章と6章の本人事実・合意は、読めた資料の根拠に限定する。「記録なし」を未達・停滞・能力不足へ置き換えない。目標が未記入なら、本人と目標を確認することを最初の問いにする。

## 保存

commit-documentの入力は次の形式。

```json
{
  "member_id": "U123EXAMPLE",
  "kind": "prep",
  "period": "2026-10-07",
  "body": "出典と参照期間を添えた6章の準備メモ本文"
}
```

```sh
python3 "<plugin-root>/scripts/people_manager.py" --workspace "<workspace>" commit-document --input "<準備メモJSON>"
```

onの場合だけ`members/<member_id>/prep/`へ保存し、既存メモは再生成しない。observe・dry-runは表示まで。保存後は本文を読み戻す。

準備メモは運用者用で、Notion活動ログDB・月次レポートへ転載せず、対象者へ通知しない。運用者通知も既定は無効で、必要なら明示設定とホストの送信ルールを確認する。

## 次のアクション

面談では、資料から断定できない目標・希望・前回アクションを本人へ確認する。確認済みの変更だけを、面談後の議事録・目標更新へ引き継ぐ。
