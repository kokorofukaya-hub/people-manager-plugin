# 定期実行

定期起動を依頼された場合だけ読む。Python helper自体にスケジューラーはない。ユーザーが選んだAIホストの定期実行機能で、同じワークスペース・プラグイン・接続を使う。

## 設定するジョブ

| 処理 | 設定案 | 実行する内容 |
|---|---|---|
| 活動収集 | 48時間おき | collectで取得範囲・完備を確認し、modeに従って保存・反映 |
| 月次 | 毎月1日09:00、Asia/Tokyo | 実行時点の前月をmonthlyで処理。既存同月は再生成しない |
| 1on1準備 | 予定開始30分前 | 条件に合う対象者だけをlocal資料で準備 |

予定登録は、プラグインのインストールとは別の操作。既存の同目的ジョブがあれば、重複登録せず設定を確認する。依頼が手動実行だけなら予定を追加しない。

## ジョブに渡す依頼文

活動収集の例。

```text
このワークスペースのPeople Manager collectを実行してください。
登録済みのactiveな対象者だけを処理し、configのmode・通知設定に従ってください。
開始時刻を固定し、媒体別の取得範囲・本人帰属・ページング完了を確認してください。
欠測は0件にせずカーソルを進めないでください。Notionの結果不明は再作成せず現物を確認してください。
Notion反映も行ってください。保存先readyと本人relationを確認し、inspectが許可した場合だけ作成してください。
保存・読み戻し・保留の結果と次の操作を短く報告してください。
```

月次の例。

```text
このワークスペースのPeople Manager monthlyを実行してください。
対象月は実行時点のAsia/Tokyoの前月です。activeな登録者だけを処理してください。
対象月と前後月のローカルactivityを読み、活動日で月を確定し、元ID・日時で重複を除いてください。
configのmodeに従い、既存同月は再生成しないでください。
Notion反映も行ってください。保存先readyと本人relationを確認し、inspectが許可した場合だけ作成してください。
非公開面談・準備メモを月次へ転載せず、人物プロフィールを変更しないでください。
対象月・保存先・Notion読み戻し・欠測を報告してください。
```

これらは登録用の設定案で、貼り付けただけでは実行済みにならない。ホストがスキル・接続を利用できるか確認してから登録する。

## Codex

Codexアプリの[Scheduled tasks](https://learn.chatgpt.com/docs/automations)を使う。対象ワークスペース・People Managerスキル・コネクターが、その実行環境でも利用できることを確認する。ローカル実行ではPC・アプリが起動し、folderが利用できる必要がある。

同じチャットへ戻る継続taskを既定にし、実行のたびに別チャットを作るstandalone taskと区別する。現在のホストが公開しているautomation toolを確認し、実際の引数仕様で指示文・周期・名前・有効状態を設定する。

導入先のチャットへ渡す登録依頼の例。

```text
この管理ワークスペースでPeople Managerの定期実行を設定してください。
このチャットを継続し、$collectを48時間おき、$monthlyを毎月1日09:00（Asia/Tokyo）に実行してください。
既存の.people-managerを使い、登録済みactive対象者だけをconfigのmodeに従って処理してください。
Notion反映も依頼します。保存先readyと本人relationを確認し、inspectが許可した場合だけ作成してください。
収集・月次の手順と固定キーを守り、失敗や欠測を0件にせず、状態不変なら通知を控えてください。
設定後、周期・実行場所・指示文を読み戻し、手動testと定期起動履歴で成功を別々に確認してください。
```

ジョブの名前、指示文、周期、Asia/Tokyoの時刻、実行場所を確認する。継続taskの通知は変化・失敗・要対応時に使い、状態不変ならquietにする。Slackへの通知設定とは別のホスト通知である。

CLI・IDEにはScheduledの管理UIがない。ホストの予定登録機能を使えない場合は「未設定」と報告し、アプリで登録できる設定案を渡す。代わりにlaunchd・cron等を無断で追加しない。

## Claude Code

ローカル正本を継続して使う場合は、[Claude Code Desktopのscheduled tasks](https://code.claude.com/docs/en/desktop-scheduled-tasks)を使う。CodeタブのRoutinesからNew routineを開き、Localを選ぶ。

対象folderをPeople Managerのワークスペースに固定し、別worktreeへの分離を無効にする。指示文、予定、permission modeを確認し、同じプラグイン・Slack・Notionが利用できる状態で登録する。

48時間おき・毎月1日など画面の選択肢で指定できない間隔は、Desktopセッションで自然文指定する。アプリが起動し、PCが起きている必要がある。sleep後のcatch-upは直近7日の未実行分を1回処理するため、実行日が予定日と異なる可能性を考慮する。

Run nowと履歴で動作を確認する。[`/loop`](https://code.claude.com/docs/en/scheduled-tasks)はセッションに依存し定期taskは7日で失効するため、継続運用の設定と同等に扱わない。

[`/schedule`のcloud routines](https://code.claude.com/docs/en/routines)は新しいcloneで動き、既存ローカル記録とローカルプラグインを自動継承しない。ローカル正本を使うこの構成へ、無設定の代替として切り替えない。

## 1on1の30分前に起動する条件

Calendar接続、登録者のメールアドレス、定期判定のホストジョブを追加で用意する。Slack・Notionだけの導入時は手動準備にとどめ、自動準備済みと表示しない。

現在から30分以内に始まる時刻付き予定を確認し、参加者メールと登録者を完全一致で照合する。終日、空き時間扱い、対象者が参加していない予定は除外する。候補が曖昧なら推測で対象を決めない。

予定がなければ新しいメモ・通知・stateを作らない。候補があれば、event IDと対象者で重複を防ぎ、1on1-prepをローカル資料だけで作る。対象者へ通知しない。

## 完了を分けて記録する

| 工程 | 確認するもの |
|---|---|
| 導入 | ホストでプラグイン・スキルを一覧表示できる |
| 予定登録 | 実行場所・指示・周期・タイムゾーンの読み戻し |
| 手動実行 | 対象スキルの実行結果、ローカル保存、Notion現物の読み戻し |
| 定期実行 | 予定から起動した履歴と、その回の対象者別結果 |

scheduled taskの登録だけで本番成功と報告しない。作成・読み戻し・定期起動が未確認なら、それぞれ未検証と書く。

## 次のアクション

初回は手動で保存と読み戻しを確認し、その後に定期ジョブを登録する。次回の定期起動履歴で完走を確認する。
